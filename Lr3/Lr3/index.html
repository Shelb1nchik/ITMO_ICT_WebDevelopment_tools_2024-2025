Лабораторная работа №3: Упаковка FastAPI приложения в Docker, работа с источниками данных и очереди

Описание выполненной работы

В рамках лабораторной работы реализована упаковка FastAPI-приложения, парсера, базы данных и фонового воркера в Docker-окружение. Все компоненты взаимодействуют через HTTP и очередь задач Celery с брокером Redis.

Структура проекта

  • main.py: точка входа FastAPI-приложения
  • parser.py: отдельный FastAPI-сервис для парсинга
  • celery_app.py: инициализация Celery
  • tasks.py: описание фоновых задач
  • auth.py: авторизация пользователей
  • connection.py: подключение к БД
  • models.py: модели SQLAlchemy
  • .env: переменные окружения

Docker и Docker Compose

Приложение и все его зависимости упакованы с использованием Docker и orchestration-файла docker-compose.yml. Созданы два Dockerfile: - Dockerfile — основной (FastAPI-приложение) - Dockerfile (parser) — для парсер-сервиса

Dockerfile (основной):

FROM python:3.10-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app
COPY .env .env

EXPOSE 8000

ENV PYTHONUNBUFFERED=1

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

Dockerfile (parser):

FROM python:3.10-slim

WORKDIR /app

COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY parser.py ./

EXPOSE 8001

ENV PYTHONUNBUFFERED=1

CMD ["uvicorn", "parser:app", "--host", "0.0.0.0", "--port", "8001"]

Очередь задач Celery

Фоновая обработка парсинга реализована с использованием Celery и Redis. Задачи описаны в tasks.py, запуск через celery -A celery_app.celery worker.

celery_app:

import os
from celery import Celery

REDIS_BROKER_URL = os.getenv("REDIS_BROKER_URL", "redis://redis:6379/0")
CELERY_RESULT_BACKEND = os.getenv("CELERY_RESULT_BACKEND", "redis://redis:6379/1")

celery = Celery(
    "parser_tasks",
    broker=REDIS_BROKER_URL,
    backend=CELERY_RESULT_BACKEND,
)

tasks:

import os
import requests
from app.celery_app import celery
from celery.utils.log import get_task_logger

logger = get_task_logger(__name__)

PARSER_URL = os.getenv("PARSER_URL", "http://parser:8001/parse")

@celery.task(bind=True)
def parse_url_task(self, url: str):
    """
    Celery-задача: делает POST-запрос к микросервису-парсеру,
    возвращает результат JSON или выбрасывает исключение.
    """
    payload = {"url": url}
    try:
        response = requests.post(PARSER_URL, json=payload, timeout=15)
        response.raise_for_status()
        data = response.json()
        logger.info(f"Parsing succeeded for {url}: {data}")
        return data
    except requests.RequestException as e:
        # Можно пробросить ошибку, чтобы Celery пометил задачу неудачей
        logger.error(f"Ошибка при парсинге {url}: {e}")
        # Если нужно, можно сделать retry: self.retry(exc=e, countdown=10, max_retries=3)
        raise e

FastAPI роуты

В main.py описан маршрут, через который ставится задача на парсинг в очередь Celery, и маршрут получения статуса задачи.

@app.post("/parse")
async def parse_endpoint(req: ParseRequest):
    """
    Получает на вход JSON с полем "url", асинхронно запрашивает страницу,
    извлекает <title> и сохраняет в таблицу pages.
    """
    url = req.url

    pool: asyncpg.Pool = app.state.db_pool  # type: ignore

    try:
        title = await fetch_and_store_title(str(url), pool)
    except HTTPException as e:
        # пробрасываем дальше HTTP-ошибки
        raise e
    except Exception as e:
        # непредвиденная внутренняя ошибка
        raise HTTPException(status_code=500, detail=f"Неизвестная ошибка при обработке: {e}")

    return {
        "message": "Parsing completed",
        "url": url,
        "title": title
    }
